# 代码审阅意见
## `src/etf_rotation/pipeline.py`
1. 一些公共的数据处理操作，比如复权能否在数据库处理好，当前使用的是原始数据，而不是归一化处理后的数据
2. 指数数据是直接读取的parquet文件，应该统一通过duckdb处理
3. build_weights这个函数内容太多，是否应该拆分成多个函数，可以讨论一下
4. 计算过程中均使用numpy或者pandas，是否需要使用pandas-ta-classic，可以讨论一下，对比代码复杂度、可读性、计算性能等方面决定
5. 关于参数的管理，后续计划要做参数搜索，每个参数要尝试很多不同的值观察回测结果，对于参数的管理方式需要升级，给出优化方案
6. 所有指标均没有落盘，后续进行回测分析无法看到指标的具体情况，考虑将指标保存到数据库，并保存对应的参数版本，另外需要指标可视化，给出优化方案

## `src/etf_rotation/backtest/run.py`
目前的回测流程中，没有充分使用bt框架的能力，需要优化。注意不要为了使用框架丧失自主性，充分考虑。充分读取bt项目文档和使用手册，将合适的功能交给bt框架。
1. 保留 bt 回测结果，开放实际持仓、交易和现金数据。
2. 让交易明细、成交成本分析和换手统计以引擎结果为依据。
3. 将 _DailyWeights 拆成现金计息与目标权重接入，后者考虑复用 WeighTarget。
4. 用内置统计交叉核对自定义指标，不必重写中文可视化。
5. 明确五相位是“目标平滑”还是“独立账户”，再决定是否使用策略树。
6. 单独设计停牌、开盘成交与跳空延迟，不把它们混入普通框架替换。
