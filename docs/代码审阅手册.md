## 3. 各模块观察要点

### 3.1 配置层

- `config/params.yaml` 是唯一参数入口，研报默认值 + H1–H10 假设都落在这里。
- `config.py` 里 `load_dotenv(_ROOT / ".env")` 在 import 时执行，所以 `.env` 的 `TUSHARE_TOKEN` 和路径覆盖项在 import 后即可用。注意：不要打印 token。
- 对照检查：`params.yaml` 里每个键都应该能在 `pipeline.py` 里找到使用处；找不到的（如 `risk.vol_target_portfolio`、`execution.hysteresis_improve`、`execution.gap_delay_pct`）说明该机制当前未接入主线。

### 3.2 数据层

- `data/paths.py` 是路径解析，默认指向 `data/bronze/tushare/tushare-f4f7c81a15b5779c/` 下的 `bars_daily.parquet` / `fund_adj.parquet` / `symbols.parquet`，可用环境变量覆盖。换数据目录时同步改这里（AGENTS.md 也提到了）。
- `calendar.py` 的 `trading_days` 从 `bars_daily.parquet` 的 `ts` 去重得到（注释 R2：warehouse 日历表为空），不是 tushare trade_cal，也不是 `warehouse.duckdb`。
- `universe.py` 的 `classify` 用名称关键词 + `fund_type` 大类做风险/债券/货币/可转债分类，这是对研报口径的近似（H8 相关）。`build_pool` 做上市天数与 20 日均成交额过滤。
- 复权口径在 `pipeline.load_prices` 与 `data/curate.adjusted_close` 各有一份：`close_adj = close * adj_factor / 末日 adj_factor`，即「以最近一期复权因子为基准的后复权」。两处逻辑一致，可交叉核对。

### 3.3 信号层

- `trend.py: momentum_score`：单序列循环实现，给纳指/黄金用。公式 `Momentum(w) = (exp(250*slope) − 1) * R²`，线性时间权重（H1）。
- `pipeline.py: momentum_panel`：同一个公式的向量化版本（`sliding_window_view`），给风险池横截面用。两者应该逐 ticker 对上，见第 4 节的复算示例。
- `reversal.py`：`zbias` 里均值/标准差都 `.shift(1)`（符合无前视纪律）；`active` 是 ZBias ≤ −0.5 且 ZBias[t] > ZBias[t−3]。
- `market_state.py`：`llt` 是 Ehlers Low-Lag Filter（H2）；`composite_score` 三指数各算 8 日斜率状态（>1.005 记 +1、<0.995 记 −1）后等权平均。

### 3.4 组合层

- `dedupe.py`：贪心去重，相关性阈值 0.80、上限 10 只。
- `hrp.py`：PyPortfolioOpt HRP 薄封装，250 日收益窗口、single linkage。
- `multi_asset.py`：多资产底仓 50 / 37.5 / 12.5；纳指/黄金各自动量 < 0 即归零。
- `risk_layers.py`：市场状态缩放、A 股趋势约束、单标的过热、波动率缩放四层。
- `defensive.py`：防守池 60 日波动 < 3%、风险调整动量前 5、同大类最多 1 只、120 日更新。

### 3.5 执行层

- `execution/phases.py`（五相位）、`hysteresis.py`（整组迟滞）、`gap_delay.py`（T+1 高开顺延）已实现且单测通过，但**主流水线没有 import 它们**（见 8.4）。`pipeline.py` 里五相位是内联的 `phase_weights` 实现，迟滞与跳空没有接入。

### 3.6 回测引擎

- `backtest/run.py`：`bt.Strategy` + `RunDaily` + 自定义 `_DailyWeights` + `Rebalance`。成本通过比例佣金回调（单边 bps），现金用 `(1+r)^(1/252)−1` 计息。
- 关键点：`run()` 的形参 `open_price` **从未被使用**，bt 用 `close_price` 成交（见 8.3）。

### 3.7 评估层

- `metrics.py: summary`：年化收益/波动、Sharpe、Sortino、最大回撤、Calmar、VaR/CVaR。
- `overfitting.py: deflated_sharpe`：Bailey-López de Prado 的 DSR 近似。
- `trades.py: build_trade_table`：从权重面板差分量推导买卖明细，成本按 8bp 估算。
- `plots.py`：8 张 plotly 图，输出自包含 HTML。

## 4. 如何观察信号（自己复算的最小例子）

先确认环境编码，再跑一小段对照：

```powershell
$env:PYTHONIOENCODING="utf-8"
.venv\Scripts\python.exe -c "
import numpy as np, pandas as pd
from etf_rotation import config
from etf_rotation.pipeline import load_prices, momentum_panel, load_indices
from etf_rotation.signals import trend, market_state as ms
from etf_rotation.data import calendar

close, opn, amt = load_prices()
logp = np.log(close)

# 1) 向量化动量面板 vs 单序列动量，应对得上
t = close.columns[0]
m21 = momentum_panel(logp, 21)
m21b = trend.momentum_score(close[t], 21)
print('momentum 最大偏差:', float((m21[t] - m21b).abs().max()))

# 2) 市场状态：三指数复合分 → 三态
idx = load_indices()
comp = ms.composite_score({'sh': idx['000001.SH'],
                           'zz2000': idx['932000.CSI'],
                           'zzhl': idx['000922.CSI']}, alpha=0.10)
days = calendar.trading_days('2019-01-01', '2026-07-31')
regime = comp.reindex(days).map(
    lambda v: 'bull' if v >= 0.35 else ('bear' if v <= -0.35 else 'range'))
print(regime.value_counts().to_dict())

# 3) 权重面板：每行和应 ≤ 1（其余为现金）
w = pd.read_parquet('reports/weights.parquet')
print('权重行和 最小/最大:', float(w.sum(axis=1).min()), float(w.sum(axis=1).max()))
"
```

这段代码里第 2 步用的是 `reindex(days)` 的**正确**取法；对比 `pipeline.py` 里的取法能立刻发现 8.1 的问题。

## 5. 如何核对数据

- 数据位置：`data/bronze/tushare/tushare-f4f7c81a15b5779c/`（ETF 日线/复权/标的）、`data/bronze/tushare/etf_rotation/`（指数 + fund_basic）。`data/warehouse.duckdb` 目前只被 `calendar.py` 之外的路径忽略，日历实际走 parquet 去重。
- 时间跨度实测：ETF 日线与上证/创业板/沪深300 到 2026-09-30；中证2000/中证红利到 2026-07-31（回测终点）。回测实际交易日 1838 天（2019-01-02 起）。
- 关键核对点：
  - 复权因子是否覆盖全部标的最新日期（后复权基准是各标的末日因子）。
  - 退市/清盘标的：当前实现里 `universe` 只做上市天数+流动性过滤，退市后的价格若存在 NaN，`backtest/run.py` 用 `ffill` 补价、并把 NaN 价格日权重归零（`w.mask(close_price.isna(), 0.0)`），可核对是否符合预期。
  - 分类口径：`classify` 的 `CONVERTIBLE_KW/MONEY_KW/BOND_KW` 关键词与 fund_type 大类是否覆盖了池子里所有关键标的，值得抽几只 ETF 人工核对。

## 8. 已发现的疑点与重点核查项

这是通读代码时实际定位到的问题，按影响排序。结论都有命令实测支撑，建议你逐条复核后再决定是否修改。

### 8.1 【高】`pipeline.py` 三处按位置索引全历史序列，与回测窗口错位约 4 年

`pipeline.py:145`：

```python
base = multi_asset.base_weights(regime.iloc[i], nas_mom.iloc[i], gold_mom.iloc[i])
```

`regime` / `nas_mom` / `gold_mom` 都是**全历史**序列（从 2015-01-05 起，约 2855 个交易日），而循环里的 `d` 来自 `calendar.trading_days(start, end)`（从 2019-01-02 起，1838 个交易日）。`.iloc[i]` 按位置取值，于是把 2015–2022 的市场状态/纳指黄金动量，错配到 2019–2026 的交易日上。

实测：`regime.iloc[i]` 与同文件 147 行正确写法 `regime.loc[d]` 在 1838 天里有 1256 天不一致（68.34%）。

影响：多资产底仓的风险预算（bull/range/bear 三态）以及纳指、黄金的进出判断都用了错位的值。这是目前最可能拉偏回测结果的一处。

建议核对方式：把 `regime` 用 `.reindex(days)` 对齐后再取（参考第 4 节示例），或把 `.iloc[i]` 全部改成 `.loc[d]`，重跑 `run_backtest.py` 对比 `metrics.json`。

### 8.2 【中】震荡市「95%」可能被扣了两次

- `portfolio/multi_asset.py:6`：range 市 `w["risk"] = 0.50 * 0.95`。
- `portfolio/risk_layers.py:4`：range 市 `base = 0.95`。

`pipeline.py` 里 `risk_budget = base["risk"] * rscale`，于是震荡市实际风险仓 = `0.5 * 0.95 * 0.95 = 0.45125`，而不是研报描述的「降至 95%」即 `0.475`。设计文档在 §2.4 和 §2.6 各描述了一次「震荡 95%」，代码可能把同一规则实现成了两处叠加。请对照研报意图确认是否应只扣一次。

### 8.3 【中】执行价是 T+1 收盘，不是 T+1 开盘；`open_price` 是死参数

`backtest/run.py:41` 的 `run(weights, open_price, close_price, ...)` 中 `open_price` 从未被使用，bt 单价格模型用 `close_price` 成交。`run_backtest.py:26` 的 `weights.shift(1)` 保证「T 日信号、T+1 生效」，但成交价是 T+1 收盘，不是研报的 T+1 开盘，也没有跳空顺延。回测报告已声明这一点，但它与 `open_price` 参数名会给人「用了开盘价」的错觉，审阅时要留意。

### 8.4 【中】反转、迟滞、跳空、过热退出、组合 34% 波动目标未接入主线

这些模块都实现并通过了单测，但 `pipeline.py` 没有 import 它们：

- `signals/reversal.py`：反转信号（震荡市「动量+反转」的“反转”没进主流水线，当前震荡市实际是纯动量排名）。
- `execution/hysteresis.py`：整组迟滞。
- `execution/gap_delay.py`：T+1 高开顺延。
- `portfolio/risk_layers.py: overheat_mask`：单 ETF 过热退出。
- `config/params.yaml: risk.vol_target_portfolio = 0.34`：组合层目标波动。

其中迟滞/跳空/过热/34% 在 `TODO.md` 和 `AGENTS.md` 的「已知尚未接入」里都有记录；但**反转信号未接入**这一点目前没有在报告差异说明里显式写出，建议补一句，或确认这是有意简化。

### 8.5 【低】参数敏感性目前只有成本一维

`run_sensitivity.py` 只扫了成本 0/8/16/24bp，`evaluation/sensitivity.py` 的 `sweep` 通用网格能力尚未被调用。动量窗口、相关性阈值、过热阈值、波动率目标等网格（AGENTS.md 阶段目标 1、`TODO.md` 阶段 B）还未落地。DSR 只对 4 个高度相关的成本变体计算，报告已注明「仅作参考不作结论」。

### 8.6 对照：哪些地方是「做对了」的

审阅时也留意这些正面锚点，避免误改：

- 无前视：`run_backtest.py:26` 的 `weights.shift(1)`；`reversal.py` 的均值/标准差 `.shift(1)`；动量窗口只用到当日及之前数据。
- 标签对齐：`market_regime()` 与 `compute_benchmark()` 都用了 `.reindex(days)`（正确），只有 `build_weights()` 里的三处 `.iloc[i]` 错了（8.1）。
- 点-in-time 资格：标的池过滤全部基于 `<= d` 的数据（`n_days.loc[d, t]`、`avg20.loc[d, t]`）。

## 9. 其他审阅建议

- 一次只改一个参数维度，改完立刻重跑并对比 `metrics.json`，否则无法归因（AGENTS.md 纪律）。
- 调参/优化前，先想清楚该机制是否适用于规则驱动策略；ML 专属技能（交叉验证、特征工程、CPCV 等）不适用，不要硬套。
- 敏感性要用「稳健性分数 + 悬崖检测」而不是只看单点最优；过拟合要用多重检验校正（试验总数 + DSR/PSR）。
- 样本外稳健性用时间子区间近似：2019–2023 vs 2024–2026，规则驱动没有训练集，不要用 K 折。
- 数据完整性建议定期跑一遍 `data/curate.validate_ohlcv` 的 OHLC 一致性、缺口、重复、复权异常检查。
- 每次审阅/改动用语义化 commit；`.env` 与 `data/` 已被 gitignore，注意不要误提交 token 或原始数据。
- 审阅交易明细时注意 `trades.csv` 是「净值口径」推导值，不是逐笔成交快照，成本是估算值。
