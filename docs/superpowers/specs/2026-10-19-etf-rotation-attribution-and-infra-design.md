## 1. 意图与动机（why）

策略机制已全部复现落地（v1.0.x，机制补全 + 执行精度 + 阶段二调参完成），但当前基线距研报仍有明显差距：候选参数 close 口径 12.31% / -12.21% / Calmar 1.01，对标研报 20.74% / -10.13% / 2.05。报告现有解释「差距主要来自换手成本」经不起推敲——**零成本下年化仅 14.69%，离 20.74% 仍差约 6 个点**，这部分是「结构性差距」，目前没有任何系统归因能说清它去了哪。

同时，参数/假设/结果管理尚未达到可支撑「大规模搜索与迭代回测」的专业标准：`run_id` 只哈希 params（缺代码/数据/执行维度）、`INSERT OR REPLACE` 覆写历史、grid 结果游离在 registry 之外、H1–H10 复现假设硬编码在代码里无法作为可搜维度。

因此下阶段做两件互为支撑的事：① 把 6 个点拆清楚、尽量逼近，逼不近也要给出可复核的解释；② 建立轻量但专业的实验基础设施，让「参数/假设/信号/结果」可版本化、可唯一对应，从而支撑 ① 的搜索与归因。信号可观测化是 ① 的归因工具。

## 2. 目标 / 非目标 / 反目标

### 目标
- **G1 差距归因**：把 20.74% vs 14.69%（零成本）的约 6 点，系统拆到「数据源 / 标的池 / 信号 / 组合 / 执行」五个桶。信号/组合/执行三桶精确量化；「数据源 / 标的池」两桶因无 Wind/研报精确输入只能给出有界上界（proxy + 显式残差），报告如实声明哪些可归因、哪些不可精确归因。
- **G2 假设敏感性**：H1–H10 全部参数化/开关化，逐项敏感性，找出真正拉开差距的假设（而非只在参数维度调）。
- **G3 工程化基础设施（轻量复用）**：`run_id` 唯一对应「参数 + 代码 + 数据 + 执行 + 信号版本」；append-only 不可变账本；grid 结果入账本；参数 schema + 命名版本；数据快照哈希。
- **G4 信号可观测化**：回测结束后逐日看到参与过决策的每个信号的值与趋势、它如何影响策略判断、如何触发交易（作为 G1 的归因工具，不改变数值）。
- **G5 前置决策落地**：默认执行口径 close → open（T+1 开盘成交）；候选参数 bull=0.30 / corr=0.85 写回 params.yaml；重跑确立新基线。

### 非目标
- 不换回测引擎（bt）；不引入商业 SDK；不做 ML 模型/特征工程。
- 不在 open 口径下重新调参（候选参数直接采纳，重调属后续可选）。
- 不存全市场全标的信号面板（范围 = 持仓 + 候选 + 关键退出点）。

### 反目标（做了反而算失败）
- 为逼近 6 点而数据挖掘/过拟合（须过 DSR / 子区间一致性 / 前视防护三道关）。
- 把基础设施做成重量级平台（违背「省开发量」，也不该为工具而工具）。
- 破坏可复现性与无前视纪律（`.shift(1)`、token 不泄露、data/ 不入库）。

## 3. 约束

- 沿用 `AGENTS.md` 全部约束：Python 3.10 / `.venv\Scripts\python.exe`；滚动统计量 `.shift(1)`、T 日信号 T+1 成交；单边 8bp / 现金 1.8%；分支 `main`；不依赖商业产品/SDK。
- 引擎保持 bt（活跃，且已适配有状态执行：OpenRebalance 开盘顺延/停牌/五相位/迟滞）。
- 基础设施复用成熟开源件：Hydra（配置 + multirun 网格）、DVC 或轻量 manifest（bronze 内容哈希）、现有 `registry.py` 修到 ml4t-registry-system 标准；不引入 MLflow/wandb。
- 可观测化与基础设施「不改数值」的重构，每个任务结束须 `IDENTICAL` 回归（weights/metrics 逐值一致）。

## 4. 已定决策（来自头脑风暴，D = decision）

- **D1 前置**：默认执行 close → open（T+1 开盘成交 + 高开顺延 + 停牌跳过）；候选参数 bull=0.30 / corr=0.85 写回 params.yaml。二者落地后重跑确立新基线（数值大概率低于 close 12.31%，接受，属「贴近研报真实机制」的代价）。
- **D2 引擎**：保留 bt，不换 vectorbt。理由：vectorbt 是回测引擎（非实验跟踪/参数管理），且向量化范式与有状态执行语义错配；本项目缺的是「基础设施」不是「引擎速度」。
- **D3 基础设施路线（轻量复用）**：Hydra（配置 + multirun 并行网格）；修 registry 到 ml4t-registry-system 标准（run_id = hash(params + git_sha + 数据快照 + 执行口径 + 信号版本)，append-only，grid 结果入账本）；DVC/轻量 manifest（bronze sha256）；quantstats 可选补 tearsheet。
- **D4 可观测化范围**：参与过决策的信号（最终持仓 + 进过候选池 + 被过热/趋势约束踢出的标的），不存全市场全量面板；观测层只读中间量、不改数值。
- **D5 假设一等公民**：H1–H10 全部参数化/开关化 + 假设账本（每条假设 → 代码位置 → 当前值 → 候选 → 敏感性状态）；「假设敏感性」= 普通网格维度。
- **D6 ml4t 清单重分类**：registry-system / canonical-schema 转 ✅，case-study-pipeline / data-export 转 🔶（已写入 AGENTS.md）。
- **D7 数据源/标的池 = 有界残差**（用户确认无 Wind）：用复权口径敏感性 + 幸存者偏差审计 + 中证2000 回补口径做 proxy 上界，报告明确声明「这部分差距无法精确归因」。
- **D8 归因锚点**：以「close + 零成本 + 默认参数 = 14.69%」为参照，使「6 点」定义不变；「执行」桶（close→open、成本）作为独立可加桶显式量化，不并进新基线净掉。
- **D9 分解方法**：固定顺序 waterfall + 显式残差桶（不用 Shapley）；每个桶标注「实测」或「有界/残差」，避免「恰好等于 6 点」的误导表。
- **D10 假设敏感性分级**：标量假设（H1/H2/H3/H4/H5/H7）进自动网格；结构/离散假设（H6/H8/H10）落 docs/assumptions.md 一次性对照；H9（复权口径）做有界 proxy。
- **D11 数据版本**：轻量 manifest（bronze 内容哈希校验），不上完整 DVC。
- **D12 信号版本**：先用 git_sha 近似（与代码版本耦合），独立信号版本化留待需要时再加。

## 5. 差距归因方法（借鉴 ml4t-exposure-analysis / case-study-pipeline）

1. **资产类别归因**：风险资产 / 纳指 / 黄金 / 防守 / 现金 逐日权重 × 收益 → 分桶贡献，回答「12% 这锅肉谁贡献的」。
2. **区间归因**：2019–2023 vs 2024–2026，分年度对标研报表 5，找差距集中在哪段。
3. **机制开关对照**：五相位 / 整组迟滞 / 反转 / 单 ETF 过热 / 34% 组合波动，逐项 on/off 看增量（已有「机制接入归因」表，扩展为可自动重算的对照）。
4. **假设敏感性**：H1–H10 逐项网格（如 H1 线性 vs 指数权重、H5 反转 50/50 vs 30/70、H7 纳指黄金退出阈值 0 vs ±5%）。
5. **集中度 / 暴露**：HHI / 有效持仓数、资产类暴露漂移，确认没有意外的集中押注。
6. **数据质量复核**：幸存者偏差（退市/清盘 ETF 是否漏掉）、point-in-time 池子无前视；tushare vs Wind 口径差异无 Wind 无法精确量化，改用复权口径敏感性 + 中证2000 回补口径做有界上界（D7）。

> 归因结果按「固定顺序 waterfall + 显式残差桶」汇总（D9）：信号/组合/执行桶实测，数据源/标的池桶为有界上界，残差单独列出，不做「恰好等于 6 点」的强求和。
